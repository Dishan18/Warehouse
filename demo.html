1. How to Run Backend & Frontend

Step A: Start Spring Boot Backend

Set your administrator password, JWT 256-bit secret, and Supabase database password in PowerShell:

PowerShell
$env:ADMIN_PASSWORD = "Admin@123" $env:JWT_SECRET = "404E635266556A586E3272357538782F413F4428472B4B6250645367566B5970" $env:DB_PASSWORD = "your_supabase_database_password" .\mvnw.cmd spring-boot:run
Console Confirmation:
Started SmartWarehouseApplication in ~15s | Tomcat on port 8080

Step B: Start React Frontend

Open a second terminal window, navigate into the frontend folder, and launch Vite:

PowerShell
cd d:\Warehouse\frontend npm run dev
Browser Access:
URL: http://localhost:3000
Vite automatically proxies /api and /ws to http://localhost:8080.

3. End-to-End Workflow & Core Functionalities

1
Authentication & Identity Token Issuance
The client sends credentials to the stateless authentication gateway. Passwords are encrypted with BCrypt (strength 10), and a signed JWT containing authority claims is issued.
POST /api/auth/login
// Request Payload: { "email": "admin@warehouse.com", "password": "Admin@123" } // 200 OK Response: { "accessToken": "eyJhbGciOiJIUzM4NCJ9.eyJzdWIiOiJhZG1pbkB3YXJlaG91c2UuY29tIiwicm9sZXMiOlsiQURNSU4iXX0...", "tokenType": "Bearer", "roles": ["ADMIN"] }
2
Catalog Structuring: Categories & Suppliers
Before products can be registered, foreign key taxonomies are created. The database enforces unique constraints on category names to avoid duplicates.
POST /api/categories & POST /api/suppliers
// Create Category: POST /api/categories { "name": "Sensors & Boards", "description": "IoT Components", "active": true } // Returns: { "id": "5dfa43f0-fd8e-48f4-841c-68ddbe563b6c", "name": "Sensors & Boards" } // Create Supplier: POST /api/suppliers { "name": "Apex Logistics", "email": "apex@supplies.com", "phone": "+1234567890", "active": true } // Returns: { "id": "8c5de530-bfb8-4856-b130-48e41f93614a", "name": "Apex Logistics" }
3
Product Inventory Registration & Status Calculation
Products bind to a Category and Supplier. Initial inventory count is evaluated dynamically: if quantity > minStock, status is initialized as IN_STOCK.
POST /api/products
{ "sku": "MCU-ESP32-901", "name": "ESP32 Dev Board", "price": 45.00, "quantity": 10, "minStock": 3, "categoryId": "5dfa43f0-fd8e-48f4-841c-68ddbe563b6c", "supplierId": "8c5de530-bfb8-4856-b130-48e41f93614a", "active": true } // 201 Created Response: { "id": "220176f6-b56b-47e8-9a44-bda962bd128a", "sku": "MCU-ESP32-901", "name": "ESP32 Dev Board", "quantity": 10, "minStock": 3, "status": "IN_STOCK" }
4
Concurrency-Safe Idempotent Outbound Stock Movement
Outbound stock deductions prevent overselling and double deductions through an integrated two-tier defense:
1. Pessimistic Row Lock: Acquires an exclusive database lock (SELECT ... FOR UPDATE) on the product row.
2. Scoped Idempotency Engine: Stores (user_id, http_method, request_uri, key) with SHA-256 payload hash in idempotency_records.
POST /api/movements/outbound (Headers: X-Idempotency-Key: demo-key-101)
// First Execution (Fresh Key): POST /api/movements/outbound Headers: [ "X-Idempotency-Key": "demo-key-101" ] Body: { "productId": "220176f6-...", "quantity": 4, "reason": "Sales Order #1" } Response (200 OK): { "beforeQuantity": 10, "afterQuantity": 6, "type": "OUTBOUND", "performedBy": "admin@warehouse.com" } // Replay with Same Key (Network Timeout Simulation): Headers: [ "X-Idempotency-Key": "demo-key-101" ] Body: { "productId": "220176f6-...", "quantity": 4, "reason": "Sales Order #1" } Response: - Returns cached response immediately (afterQuantity: 6). - Real Database Quantity remains 6 (DOUBLE DEDUCTION PREVENTED). // Tampered Key Reuse (Different Payload): Headers: [ "X-Idempotency-Key": "demo-key-101" ] Body: { "productId": "220176f6-...", "quantity": 2, "reason": "Tampered" } Response (422 Unprocessable Entity): "Idempotency key reused with different request payload"
5
Real-Time WebSocket Stock Alert Broadcast
When inventory drops below the alert threshold (e.g., deducting 4 more units: 6 -> 2, below minStock of 3), the backend updates product status to LOW_STOCK and asynchronously broadcasts a STOMP frame over WebSocket.
STOMP Topic: /topic/stock-alerts
// Client WebSocket Connection: ws://localhost:3000/ws (proxied to ws://localhost:8080/ws) Destination: /topic/stock-alerts // Received Alert Frame: { "productId": "220176f6-b56b-47e8-9a44-bda962bd128a", "productName": "ESP32 Dev Board", "sku": "MCU-ESP32-901", "quantity": 2, "minStock": 3, "type": "LOW_STOCK", "createdAt": "2026-10-12T21:40:00" }
Frontend Response: The top navigation Bell Icon badge increments to show unread alerts, and the item displays in the "Low stock alerts" dropdown drawer.
6
Global Settings & Currency Customization (INR / USD)
Under Settings (/settings), administrators can configure the Warehouse Name, Low Stock Threshold, and global Currency (including INR, USD, EUR, GBP).
PUT /api/settings
{ "warehouseName": "SmartWarehouse Central", "currency": "INR", "lowStockThreshold": 10, "notificationsEnabled": true } // Effect: - Products table renders prices as: ₹45.00 - Reports page renders total inventory value as: ₹49,189.94 - Audit log records mutation in table audit_logs.

4. One-Click Verification Script (PowerShell)

Run this self-healing script in PowerShell to verify every backend and database subsystem sequentially:

PowerShell Full Verification
# 1. Login $login = Invoke-RestMethod -Uri "http://localhost:8080/api/auth/login" -Method Post -ContentType "application/json" -Body '{"email":"admin@warehouse.com","password":"Admin@123"}' $TOKEN = $login.accessToken Write-Host "1. Authentication: SUCCESS" # 2. Category: Reuse existing or create unique $cats = Invoke-RestMethod -Uri "http://localhost:8080/api/categories" -Method Get -Headers @{ Authorization = "Bearer $TOKEN" } $CAT_ID = if ($cats.content.Count -gt 0) { $cats.content[0].id } else { (Invoke-RestMethod -Uri "http://localhost:8080/api/categories" -Method Post -ContentType "application/json" -Headers @{ Authorization = "Bearer $TOKEN" } -Body '{"name":"Tools","description":"Tools","active":true}').id } Write-Host "2. Category ID: $CAT_ID" # 3. Supplier: Reuse existing or create unique $sups = Invoke-RestMethod -Uri "http://localhost:8080/api/suppliers" -Method Get -Headers @{ Authorization = "Bearer $TOKEN" } $SUP_ID = if ($sups.content.Count -gt 0) { $sups.content[0].id } else { (Invoke-RestMethod -Uri "http://localhost:8080/api/suppliers" -Method Post -ContentType "application/json" -Headers @{ Authorization = "Bearer $TOKEN" } -Body '{"name":"Apex Logistics","email":"apex@test.com","active":true}').id } Write-Host "3. Supplier ID: $SUP_ID" # 4. Product: Create fresh item $rand = Get-Random -Minimum 1000 -Maximum 9999 $prod = Invoke-RestMethod -Uri "http://localhost:8080/api/products" -Method Post -ContentType "application/json" -Headers @{ Authorization = "Bearer $TOKEN" } -Body (@{ sku="SKU-$rand"; name="Product $rand"; price=25.00; quantity=10; minStock=3; categoryId=$CAT_ID; supplierId=$SUP_ID; active=$true } | ConvertTo-Json) Write-Host "4. Created Product: $($prod.name) (Stock: $($prod.quantity), Status: $($prod.status))" # 5. Outbound Movement: Deduct 4 (10 -> 6) $key = "key-$rand" $move = Invoke-RestMethod -Uri "http://localhost:8080/api/movements/outbound" -Method Post -ContentType "application/json" -Headers @{ Authorization = "Bearer $TOKEN"; "X-Idempotency-Key" = $key } -Body (@{ productId=$prod.id; quantity=4; reason="Test" } | ConvertTo-Json) Write-Host "5. Deduction: $($move.beforeQuantity) -> $($move.afterQuantity)" # 6. Idempotent Replay (Verify double deduction prevented) $replay = Invoke-RestMethod -Uri "http://localhost:8080/api/movements/outbound" -Method Post -ContentType "application/json" -Headers @{ Authorization = "Bearer $TOKEN"; "X-Idempotency-Key" = $key } -Body (@{ productId=$prod.id; quantity=4; reason="Test" } | ConvertTo-Json) $dbProd = Invoke-RestMethod -Uri "http://localhost:8080/api/products/$($prod.id)" -Method Get -Headers @{ Authorization = "Bearer $TOKEN" } Write-Host "6. Replay Cached: $($replay.afterQuantity) | Actual DB Stock: $($dbProd.quantity) (NO DOUBLE DEDUCTION)" # 7. Low Stock Transition (6 -> 2, below minStock of 3) $low = Invoke-RestMethod -Uri "http://localhost:8080/api/movements/outbound" -Method Post -ContentType "application/json" -Headers @{ Authorization = "Bearer $TOKEN"; "X-Idempotency-Key" = "low-$rand" } -Body (@{ productId=$prod.id; quantity=4; reason="Deplete" } | ConvertTo-Json) $finalProd = Invoke-RestMethod -Uri "http://localhost:8080/api/products/$($prod.id)" -Method Get -Headers @{ Authorization = "Bearer $TOKEN" } Write-Host "7. Final Stock: $($finalProd.quantity), Status: $($finalProd.status) (WebSocket alert fired!)"
